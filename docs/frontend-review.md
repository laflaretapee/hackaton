## Focused re-review status

- **Finding 1 resolved:** `frontend/src/admin.tsx:151` replaces the local form with the successful server settings response and blanks both secret fields. This synchronizes disabled/mock switches after explicit deletion. Regression covers Telegram clear followed by another save; shared response handling also applies to RouterAI.
- **Finding 2 resolved, including account cache isolation:** `frontend/src/App.tsx:75` cancels and removes account-scoped query caches on `/me` 401 and again before a successful login transition. `finishLogin` displays a boot gate until the new `/me` resolves, preventing prior cached identity from rendering. The earlier partial fix was insufficient: with production `staleTime:15000`, Alice's cached private chat remained visible after Bob logged in. The strengthened regression now covers that transition, deliberately delayed new `/me`, old in-flight requests resolving afterward, absence of prior identity/content throughout DOM updates, fresh `GET /chat`, and removal of cached tasks/dashboard/requests.
- **Finding 3 resolved:** `frontend/src/pages.tsx:888` clears optimistic state in `finally`; draft is cleared only after success. `useAction` now invalidates on settlement, so history refetches even after partially persisted failures. Failure regression confirms typing disappears and draft remains retryable.
- **Finding 4 resolved:** `frontend/src/pages.tsx:1646` renders exam score, timestamp, recommendation, question feedback, answers, and explanations in mentor intern details, with an empty state. Regression confirms score and recommendation.
- **Backend long-message issue resolved in source:** `backend/ai.go:110` bounds the derived article search query to 200 runes independently of the full chat message.
- **Independent verification:** reran all 39 tests after the strengthened account-isolation regression; all passed. TypeScript and Vite production build passed after the cache fix. Independent V8 coverage run: 92.56% statements/lines, 86.75% branches, 90.41% functions. All four original findings are resolved in source, with no remaining blocker from this focused review. Final updated frontend has not yet been redeployed at this review point.

## Actionable findings

1. **P1 — Clearing an integration secret leaves stale settings that break the next save.** `frontend/src/admin.tsx:10`, `AdminSettings` clear mutation and save success handler. With a saved, enabled Telegram integration, click **Удалить токен → Удалить секрет**, then **Сохранить настройки**. The clear request sends `telegram_enabled:false`, but local `form.telegram_enabled` stays `true`; the next save sends `true` without a token and fails backend validation. RouterAI has the same issue with `ai_mock_mode`: clearing forces mock mode only in the outgoing payload, while local form retains live mode. Synchronize form from the successful server response, including nonsecret fields, and blank only secret inputs. Mounted React reproduction confirmed Telegram request flags `[false + clear, true without clear]`.

2. **P2 — An expired session leaves the authenticated shell visible and gives no usable sign-in transition.** `frontend/src/App.tsx:12`, `UserApp`. After successful `/me`, make a subsequent `/me` refetch return 401 (for example session expiry plus window focus). React Query retains prior successful `me.data` after a refetch error, so `if(!me.data)` does not select Login; protected pages remain visible while mutations fail with sign-in errors. Explicitly handle `ApiError.status === 401`, clear account-scoped cached data, and enter login. Mounted React reproduction confirmed the profile shell remains visible and Login is absent after invalidating `/me` with an expired session. Normal **Выйти** from `/profile` was separately tested and works because navigation causes a new query after cache clearing; it is not a finding.

3. **P2 — Failed AI requests leave a permanent typing indicator and unsaved optimistic message.** `frontend/src/pages.tsx:19`, `ChatPage` send mutation. Make `POST /api/chat` fail (network failure, 502, or configuration error). `setOptimistic('')` runs only on success, so the submitted message and **AI-buddy готовит ответ** remain forever alongside the error. Subsequent refetch can also display the persisted server user message plus this optimistic copy. Clear optimistic state on settlement/error, retain the editable draft for retry, and refetch chat if the server may already have saved the user message. Mounted React reproduction confirmed typing remains after POST 502.

4. **P2 — Mentor intern detail omits available exam results and recommendations.** `frontend/src/pages.tsx:28`, `InternDetail`. Sign in as the assigned mentor and open an intern who has completed an exam. `/interns/:id` already returns `attempts`, but the page renders only tasks, requests, and meetings; mentors cannot inspect test scores, answer feedback, or recommendations. This misses master spec §12.3 and the learning oversight goal. Render recent attempts with scores, timestamps, feedback/weak topics, and recommendations without exposing private chat messages.

## Backend issue discovered through frontend review

- `backend/ai.go:21` passes the complete chat message to `searchArticles`; `backend/domain.go:14` rejects search queries longer than 200 runes, while the chat UI permits 4000 and the chat handler intends 6000. A 201-character question is rejected before AI execution. Forwarded to the backend implementer; fix by deriving/bounding the search query independently of the chat message.
