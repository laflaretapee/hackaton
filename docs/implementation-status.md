## Реализовано

React/TypeScript/Vite SPA, Go API и PostgreSQL 17. Кабинеты стажёра, наставника и руководителя; отдельная админка. Сохраняемые профили/команды, задачи и прогресс, полнотекстовая база знаний, занятия и серверная проверка экзаменов, личный AI-чат с источниками, mock-заявки с явным подтверждением и согласованием закреплённым наставником, встречи и настройки напоминаний.

Админка сохраняет Telegram token/username/enabled, RouterAI key/base URL/model, режим AI, лимиты и URL приложения. Секреты шифруются AES-256-GCM в БД и возвращаются только как флаги наличия. Пустой ввод сохраняет прежний секрет; удаление выполняется явно. Есть проверка Telegram getMe, каталога RouterAI и принудительного tool call выбранной модели; административный аудит без секретов.

Backend реализует Telegram регистрацию и подписанный Mini App вход, одноразовый вход в браузер с подтверждением ботом, polling с отдельными offset для ботов и ограниченными повторными попытками, scheduler с claim/retry. Реальный RouterAI вызывается только сервером; инструменты проверяют пользователя и не создают заявки без подтверждения. При отсутствии ключей AI явно показывает деморежим.

Подготовлены 15 статей, 10 занятий/экзаменов по 5 вопросов, 8 направлений, 8 наставников, 8 стажёров и 2 руководителя; различные результаты, заявки и встречи. Seed идемпотентен и не сбрасывает прогресс при перезапуске.

Первый тест аварии через `docker kill` был некорректен: Docker счёл это ручной остановкой и не перезапустил контейнер. API восстановлен вручную, затем корректный тест через SIGKILL процесса подтвердил автоматический restart. Это не ошибка бизнес-логики приложения.

Последнее исправление: удаление Telegram-профиля атомарно удаляет также его регистрационное состояние и незавершённый одноразовый вход. Полный набор тестов и отдельный регрессионный тест проверяют сохранение чужого состояния и повторную регистрацию с тем же Telegram ID.

## Ограничения, которые остаются

1. Токены Telegram и RouterAI не предоставлены. Реальные регистрация/доставка Telegram и ответы выбранной модели ещё не проверены с настоящими ключами. HTTP-fixture тесты не выдаются за такую проверку. Добавьте ключи в `/admin`, сохраните и проверьте соединения. Для реального согласования зарегистрируйте реального наставника той же команды: публичные демонаставники изолированы от Telegram-профилей.
2. Корпоративные доступы имитируются; самостоятельный выбор роли не заменяет IAM/SSO. Используются синтетические данные и процессы, проект не официальный сервис Авито.
3. Один backend-процесс обслуживает API/polling/scheduler. Строго exactly-once Telegram после сбоя между внешней отправкой и DB acknowledgement не гарантируется.
4. Хранилище гибридное: реляционные владельцы/команды/сессии и индексированные JSONB доменные записи; полного набора нормализованных таблиц исходного ТЗ нет. Семантических embeddings нет, работает PostgreSQL FTS. Отдельный AI-конвейер учебных рекомендаций заменён детерминированной обратной связью и контекстным AI-чатом. Сводка руководителя ограничена выбранной командой; отдельного сравнения нескольких команд и наставников нет.
5. Нагрузочные испытания, бизнес-эффект, backup вне VPS и корпоративные интеграции не проверены/не настроены. Видео не записано; подготовлен воспроизводимый сценарий. Домен sslip.io пригоден для текущего демо; собственный домен можно настроить по инструкции.

Финальный релиз: бинарник собран Go 1.27.4. SHA-256 бинарника и HTML записаны в `docs/release-checksums.txt`; после установки последнего исправления три контейнера healthy, backup/restore повторно PASS. Финальный публичный протокол содержит 25 успешных проверок.
