# Презентация AI-buddy

Готовый PDF: `output/pdf/ai-buddy-presentation.pdf` (12 страниц, русский язык). Сайт опубликован: https://ai-buddy.85.159.231.99.sslip.io. Презентация описывает продукт, архитектуру и подтверждённое развёртывание MVP; успешный live-вызов Telegram/RouterAI пока не заявляется.

## План выступления

1. **AI-buddy.** Единая точка входа в адаптацию: знания, действия, обучение, прогресс. Демонстрационный проект по кейсу Hack&Change 2026, не официальный сервис Авито.
2. **Проблема.** Инструкции, доступы и учебные шаги разбросаны. Повторяющиеся вопросы занимают внимание наставника; стажёру трудно понять следующий шаг.
3. **Аудитория.** Стажёр получает понятный план; наставник - видимость и согласование; руководитель - агрегаты своей команды.
4. **Решение.** План, база знаний, AI с источниками, подтверждаемая заявка, уроки и mock-экзамены, встречи и напоминания.
5. **Путь пользователя.** Telegram/демовход → команда → задача → вопрос → источник → подтверждение → согласование → обновлённый прогресс.
6. **Ключевой сценарий.** Запрос доступа становится проверяемой записью с историей. Mock не выдаёт настоящих прав. Учебная оценка рассчитывается детерминированно.
7. **Архитектура.** React/Nginx → Go-монолит → PostgreSQL. Bot polling и scheduler внутри Go-процесса. RouterAI и Telegram вызываются на сервере.
8. **AI.** Retrieval по базе знаний, контекст текущего пользователя, серверные инструменты и ссылки на существующие разделы. Модель не определяет права и не заменяет проверку результата.
9. **Безопасность.** Серверные роли/владение, проверка Telegram, защищённые сессии, отдельный admin-вход и зашифрованные настройки. Демо-роль не заменяет IAM.
10. **Внедрение.** HTTPS-деплой подтверждён: 3 сервиса Compose healthy, 19 публичных API smoke-проверок пройдены. Настоящие Telegram/RouterAI требуют ключей. Корпоративные интеграции подключаются адаптерами.
11. **Метрики.** Польза - гипотеза. Проверять долю вопросов с источником, время до выполнения шага и число рутинных обращений; сравнивать пилотную и контрольную группы. Фактический эффект пока не измерен.
12. **Развитие и текущие границы.** SSO, IAM/Service Desk, календарь, улучшение поиска, аудит и пилот. Уже проверены HTTPS, API smoke, экран 360 px без горизонтального переполнения и восстановление backup. Live-бот и LLM требуют ключей и отдельных проверок; видео ещё предстоит записать.

## Проверяемые утверждения и границы

В презентации нет выдуманных результатов покрытия, нагрузочного теста, скорости AI или экономии времени. Публичный HTTPS-адрес и API проверены; Telegram-токен и RouterAI-ключ пока не предоставлены, поэтому реальные вызовы этих сервисов не проверены. Доступы к корпоративным ресурсам остаются mock. Фактические результаты запуска и тестов нужно брать из `docs/implementation-status.md`, а API - из `docs/api-contract.md`. Текст выступления следует синхронизировать с этими результатами непосредственно перед защитой.

Подтверждённые дополнительные результаты на момент обновления: frontend - 39 тестов, 92,56% строк, 86,75% ветвей и 90,41% функций; admin login и сохранение настроек проверены визуально; восстановление backup проверено на 10 таблицах. Итоговый backend coverage уточняется отдельно и здесь не объявляется достигшим целевого порога. Seed содержит 15 статей, 10 занятий, 8 синтетических стажёров, 8 наставников и 2 руководителей. Это объём демоданных, а не результат реального внедрения.
