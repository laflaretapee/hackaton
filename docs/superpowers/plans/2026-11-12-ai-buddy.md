# AI-buddy Implementation Plan
> **For agentic workers:** use subagent-driven-development for independent backend/frontend tasks and inline deployment.
**Goal:** working deployed onboarding MVP with protected Telegram/RouterAI admin configuration.
**Architecture:** Go REST monolith, PostgreSQL, React SPA, nginx, Compose. Bot polling and scheduler colocated with API for single instance MVP.
**Tech Stack:** Go stable, PostgreSQL 17, React, TypeScript, Vite, TanStack Query, Lucide.
**Spec:** docs/master-spec.md and docs/superpowers/specs/2026-11-12-ai-buddy-design.md

## Global Constraints
- Never expose credentials in frontend, logs, Git or API responses.
- Existing server applications must remain running.
- Demo and real external providers clearly identified.
- Contract docs/api-contract.md is integration authority.

## Review Focus
- Public demo login must never grant admin permissions.
- Cross-user mutations and mentor approvals require ownership.
- Provider failures must not silently become AI success.
- Empty admin secrets preserve existing values and cannot leak back.
- Progress changes only after completed business operations.

### Task 1: Backend
Files backend/**. Build schema, seeds, protected API and real integration clients. Write meaningful failing tests first for auth signatures/age, role ownership, settings encryption/masking, scoring/progress. Implement API contract. Run go test -race ./... and coverage; report gaps. Seed all directions, substantive KB sections and exams. Implement polling and notification retries.

### Task 2: Frontend
Files frontend/**. Build responsive Russian product SPA on contract. Start tests for workflow forms and routing/auth states, implement intern/mentor/manager/admin screens with loading/errors. Run tests/coverage and production build. Do not invent backend responses.

### Task 3: Infrastructure and documentation
Files deploy/**, scripts/**, specs/**, README, docker-compose.yml, docs/**. Isolated VPS deployment, backup scripts, TLS, user instructions and demo/presentation materials.

### Task 4: Verification and review
Test deployed end-to-end API journey, browser desktop/mobile, admin security/masking; independent review of backend/frontend. Correct findings, repeat relevant checks. Record actual outcomes and remaining external credentials.
