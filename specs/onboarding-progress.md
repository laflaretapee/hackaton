# SDD: план адаптации и прогресс

Статус: спецификация приёмки MVP. Контракт: `docs/api-contract.md`; ошибки `{error:string}`.

## Цель и контекст

Показать стажёру следующий шаг и сохранить фактическое выполнение задач. Наставник видит только назначенных стажёров, руководитель - разрешённые командные агрегаты. Проценты выводятся из записей, а не из статичного демотекста или ответа AI.

## Инструменты и входы

- `GET /api/tasks` → `Task[] {id,title,description,status,kind,due_at,article_id,priority}`; `kind` равен `manual|access|exam`.
- `PATCH /api/tasks/:id {status:"in_progress"|"completed"}` изменяет только manual-задачи.
- `GET /api/dashboard` → `{progress,completed,total,tasks,meetings,requests,attempts,interns,stats,team_stats}`. `stats`: `interns,mentors,teams,average_progress,ai_messages`; `team_stats`: `[{team_name,interns,progress}]`.
- `GET /api/interns` → `[{id,name,team_name,progress,completed,total,weak_topics:string[]}]`.
- `GET /api/interns/:id` → dashboard и `user`.
- `POST /api/interns/:id/tasks {title,description,due_at,article_id?}` → `Task` для разрешённого наставнику стажёра.
- AI может читать собственный прогресс через серверный инструмент `get_onboarding_progress()`, но не менять его свободным текстом.

## Выходы и бизнес-правила

Прогресс - процент завершённых задач среди всех задач пользователя; при `total=0` результат равен 0. На клиенте показываются также `completed/total`. Access-задачи меняются после бизнес-перехода заявки, exam-задачи - по правилам прохождения экзамена. Допустимые отображаемые состояния плана: не начато, в работе, ожидание согласования, выполнено, блокировка; строковый enum чтения сверяется с backend. После мутации клиент перечитывает связанные dashboard/списки.

## Ошибки и ограничения

Чужой ID задачи, попытка вручную закрыть access/exam, невалидный статус, пустое название и недопустимая дата не изменяют данные. Частичная ошибка не должна показывать новый процент без успешного сохранения. Аналитика демобазы не является доказательством ускорения реальной адаптации.

## Безопасность

Владение и назначение наставника проверяются для каждого ID сервером. Клиент не присылает новый процент и не может подменить владельца. Контекст AI ограничен разрешёнными данными. Создание задач не даёт наставнику право назначать себе произвольного стажёра.

## Критерии приёмки

1. Завершение одной manual-задачи меняет счётчик и процент согласно данным.
2. Reload сохраняет результат; наставник и стажёр видят согласованные значения.
3. Прямой PATCH access/exam отклоняется.
4. У пользователя без задач нет NaN и деления на ноль.
5. Чужой стажёр не доступен при подмене ID.

## Проверка

Unit: 0/0, 0/N, N/N, округление, недопустимые переходы. API: изменение manual-задачи, отказ для access/exam, создание наставником, межпользовательская изоляция. E2E: dashboard до/после → reload → кабинет наставника. Реальные команды и экспериментальная продуктовая аналитика не входят в синтетический seed.
