# SDD: роли и границы данных

Статус: нормативная матрица доступа для проверки реализации. HTTP-контракт: `docs/api-contract.md`; ошибки `{error:string}`. UI-скрытие кнопок не является контролем доступа.

## Цель и входной контекст

Защитить профили, историю AI, заявки и прогресс. Контекст каждой операции: серверная сессия, текущая роль, команда, назначение наставника и владелец ресурса. Роли `intern`, `mentor`, `manager` относятся только к демонстрационным данным; администратор имеет отдельную авторизацию.

## Инструменты и разрешения

| Операция | Intern | Mentor | Manager |
| --- | --- | --- | --- |
| `/api/me`, собственные настройки, logout | свой профиль | свой профиль | свой профиль |
| Собственная история `/api/chat` | своя | своя | своя |
| Изменение manual `/api/tasks/:id` | свои задачи | только при разрешённом сервером владении | только при разрешённом сервером владении |
| `/api/requests` | свои заявки | заявки назначенных стажёров | разрешённый командный обзор без согласования |
| `/api/requests/:id/decision` | запрещено | назначенные стажёры | запрещено |
| `/api/interns`, `/api/interns/:id` | запрещено | назначенные стажёры | разрешённые стажёры своей команды |
| Назначение задач/встреч `/api/interns/:id/...` | запрещено | назначенные стажёры | запрещено |
| `/api/dashboard` | собственный прогресс | разрешённые стажёры | командные агрегаты |
| `/api/admin/*`, кроме login | запрещено | запрещено | запрещено |

Матрица задаёт минимальные границы. Если интерфейс не использует необязательный обзор, endpoint может возвращать меньший разрешённый набор; расширять область сверх матрицы нельзя. Общие демоматериалы базы знаний доступны авторизованным ролям.

## Выходы

Разрешённые запросы возвращают только разрешённые записи/агрегаты. ID передаётся строкой, но не является секретом или основанием доступа. Неавторизованное или запрещённое действие не изменяет состояние. `POST /api/admin/login {password:string}` открывает отдельную admin-сессию; logout закрывает её. `GET /api/admin/settings` возвращает только флаги наличия секретов, не значения.

## Ошибки и ограничения

Проверяются отсутствие/просрочка сессии, чужой ID, смена команды, чужая заявка и неразрешённая мутация. Ошибки не раскрывают внутренние SQL/секреты и по возможности не подтверждают существование чужих приватных записей. Самовыбор роли в деморежиме не является production-моделью доверия; реальное внедрение требует IAM/SSO и назначения ролей.

## Безопасность администратора

`PUT /api/admin/settings` шифрует Telegram/RouterAI-секреты серверным ключом; пустая строка сохраняет существующий секрет, явные `clear_telegram_token`/`clear_routerai_key` удаляют. Включение ненастроенной интеграции отклоняется. RouterAI URL ограничивается разрешённым origin для защиты от SSRF. Тесты `/api/admin/test/telegram` и `/api/admin/test/routerai` не обходят admin-auth. `GET /api/admin/audit` не содержит значений секретов.

## Критерии приёмки

1. Прямой API-запрос запрещённого действия отклоняется независимо от UI.
2. Наставник A не читает/не меняет стажёра наставника B.
3. Manager не получает сведения другой команды и не согласует заявку.
4. Публичный выбор роли не открывает admin API.
5. Настройки и audit не раскрывают токен/ключ даже после сохранения.

## Проверка

Табличные API-тесты по роли × endpoint × свой/чужой ресурс; отрицательные проверки мутаций с последующим чтением БД. Отдельно: Origin/CSRF, logout, удаление профиля, шифрование/маскирование, очистка и ненастроенная интеграция. E2E переключает демопрофили и проверяет серверные отказы. Фактическая полнота и coverage публикуются только по результатам запуска тестов, не выводятся из этой спецификации.
